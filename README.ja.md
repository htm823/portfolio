## Background

制作物を紹介すること、開発におけるスタンスを伝えることを目的に制作しました。

単に制作物を並べるのではなく、試行錯誤や実装の工夫を提示することにより、ケーススタディとして制作物を見せられるサイトを目指しました。

複雑さや曖昧さを構造化し、認知負荷を下げることを設計思想としています。

## Technology Choices

情報設計とレスポンシブデザインの実装に重点を置くため、フレームワークは使用せず、基本的なWeb技術を採用しました。

このサイトの目的は、制作物を紹介することと開発におけるスタンスを伝えることです。

そのため、訪問者にどの情報をどの順序で見せるかという情報設計に重点を置く必要があると考えました。

シンプルな技術スタックを選択したことで、レイアウトやコンテンツの階層構造により多くの時間を充てることができました。

## System Design

モノトーンを基調とし、1色のブランドカラーをアクセントとして使用したシンプルなデザインを採用しました。

装飾的な要素は最小限に抑え、認知負荷を下げることで、訪問者がコンテンツに集中できるよう設計しています。

また、視覚的な理解を助けるため、各ページでは内容に応じた画像やアイコンを使用しています。

各ページのHeroセクションでは、ページの役割を瞬時に把握できるようにするため、画像とテキストで概要を提示しています。

制作物詳細ページにおける使用技術や実装機能のセクションには、情報をスムーズに理解できるようアクセントカラーのアイコンを追加しました。

## Implementation Highlights

初めてサイトへアクセスした際、アニメーションが表示されます。

実装において、アニメーションのタイミング制御を工夫しました。`sessionStorage` と JavaScript の `setTimeout()` を組み合わせることで、初回アクセスかどうかを判定するとともに、アニメーションを適切なタイミングで開始する処理を追加しました。

サイトはブラウザの言語設定に応じて対応する言語ページへ自動的にリダイレクトされます。そのため、言語判定が完了した後にアニメーションを実行する仕様としました。これにより、ユーザーにとって好ましい言語でコンテンツに触れることができるようになっています。

## Challenges & Solutions

SCSSファイルをどのように分割するかという点が課題でした。

個々のカードやカード一覧のようなUIは、再利用する回数が多いため、コンポーネントとして切り出す構成にしました。一方、それ以外の各セクションについては、独立したコンポーネントとして管理すべきか、ページ専用のスタイルとして管理すべきか、判断に時間を要しました。

現状、将来的な拡張性を考慮し、各セクションを個別のコンポーネントとして分割しています。再利用性は向上しましたが、またスタイルの重複を減らす余地があると考えています。今後、SCSSをリファクタリングする際、DRY原則の強化を行います。
